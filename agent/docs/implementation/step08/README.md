# Step 08 — 현황·원인 분석 보고서

사용자 흐름도의 빨간 **② 현황·원인 분석 보고서**를 구현한다. **③ 복지 매핑은 사용자가 별도 확인하므로 이번 구현에서 제외한다.** 대응안 추천이나 두 번째 예방 대응 보고서를 자동 생성하지 않는다.

## 처리 흐름

1. 검증된 시군구·관측월·성별·연령의 활동과 I5/MOIS 배경으로 기존 관측 보고서를 생성·저장한다.
2. 저장된 관측 보고서의 범위를 고정해 AI가 공개 지역 맥락을 조사한다.
3. 확인한 지역 맥락, 가능한 원인 가설, 출처와 기간·지역 한계, 추가 확인 질문을 구분한다.
4. 조사 결과는 원래 관측 보고서를 변경하지 않고 `parent_report_id`로 연결한 별도 보고서로 저장한다.
5. 저장된 보고서는 대화나 브라우저 기록이 없어도 상단 **저장된 보고서**에서 조회·열람·내려받을 수 있다.

조사에 실패하면 저장된 관측 보고서와 **원인 조사 미완료 / 다시 조사**를 표시한다. 검색은 실행했으나 적절한 근거를 확보하지 못한 경우는 `no_evidence`이며, 근거가 있는 원인 후보를 생성한 성공과 구분한다. 보고서 요청만으로 복지 조회를 시작하지 않는다.

## API와 저장

| 요청 | 동작 |
| --- | --- |
| `POST /api/model/analysis-reports` | 기존 검증 관측 보고서 생성·자동 저장 |
| `POST /api/model/analysis-reports/{report_id}/investigate` + `{}` | 저장된 범위의 외부 맥락 조사·원인 가설 보고서 저장 |
| `GET /api/model/analysis-reports` | 관측 보고서와 조사 보고서의 목록·조사 상태·원본 연결 조회 |
| `GET /api/model/analysis-reports/{report_id}` | 구조화 결과와 저장된 Markdown 전문 조회 |

클라이언트가 조사 요청에서 관측값·범위·제공자를 바꿀 수 없다. 조사 경로에는 기존 `investigate` 권한을 적용한다. 기관 모드는 승인된 조사 모델 구성이 없어 외부 조사를 거절하며, 개인 구독을 사용하지 않는다.

SQLite의 `analysis_report_research`는 원본 보고서와 조사 프롬프트 버전별 실행을 관리한다. 완료된 보고서는 재사용하며 동시 요청은 409와 재시도 안내를 반환한다. 실패한 작업의 점유를 해제하고, 프로세스 중단으로 남은 점유는 10분 후 다시 요청할 수 있다. 최종 보고서 저장과 완료 표시를 같은 트랜잭션으로 처리한다.

기존 관측 보고서의 자료 버전·수치·분류·품질 상태는 불변이다. 조사 중 최신 번들이 바뀌어도 이미 저장된 관측 시점에 대한 조사임을 유지한다. 새로운 자료로 분석하려면 새로운 관측 보고서를 생성한다.

## 외부 조사 범위

- 기존 `DONGHAENG_PROVIDER` 설정을 따른다. 기본은 로그인된 Codex 구독이며, `openai_responses`를 명시한 경우에만 설정한 API 제공자를 사용한다. 인증 실패 시 다른 과금 경로로 전환하지 않는다.
- 지역명, 관측월, 성별·연령별 **집계 관측**과 지역 배경이 구성된 외부 모델로 전달된다. 개인 원자료나 복지 DB 접속 정보를 전달하지 않는다.
- 별도 조사 제공자는 읽기 전용 웹 검색만 허용한다. 기존 복지/조사 제공자의 권한을 확장하지 않는다.
- 현재 출처는 `go.kr`, `kosis.kr`의 공개 HTTPS HTML/텍스트로 한정한다. 최대 12번의 웹 호출, 최대 4개 출처를 사용한다. PDF 전용·로그인·접근 불가 자료는 검증 근거로 사용하지 않는다.
- 출처를 서버에서 다시 읽어 짧은 원문 발췌의 일치 여부와 내용 해시를 확인한다. 외부/비공개 IP, 허용 밖 도메인 및 리다이렉트, 과도한 응답을 차단한다.
- 원문 접근과 발췌 일치 검증은 **원인 입증이 아니다**. 발행일·자료 대상 기간·지역 관계는 모델 추출값으로 표시하며, 원인 후보에는 출처와 해석 한계를 함께 남긴다.
- 검색을 수행하지 않은 응답, 미등록 출처 인용, 범위 변경, 불완전 응답을 완료 보고서로 저장하지 않는다.
- `quality_status=hold`, `operational_alert_allowed=false`와 결정적 분류를 유지한다. I5를 고립률·개인 진단으로 해석하지 않는다.

`DONGHAENG_ANALYSIS_RESEARCH_TIMEOUT_SECONDS`로 Codex 조사 제한 시간을 설정할 수 있다(기본 120초, 최대 180초). HTTP 출처 확인은 별도로 제한된다.

## 검증 상태 — 2026-10-25

- 보고서·저장·재시도·동시 요청·권한·조사 엔진 검사 **106개 통과**. 기존 조사 모드까지 포함한 검사는 상위 `agent/.venv`의 설치된 의존성을 사용했다.
- 현재 전체 프런트엔드 검사 **185개 통과**, TypeScript 및 Vite 빌드 통과.
- 외부 호출을 막은 별도 로컬 시험 서버에서 합성 조사 결과를 사용해 실패 후 재시도, 저장 보고서 다운로드, 390px 모바일 배치, 브라우저 기록 삭제 후 서버 재조회를 확인했다. 이는 실제 외부 조사 성공 증거가 아니다. 시험 서버는 종료했다.
- 원문 검증·모델 전송 경계는 합성 입력과 가짜 제공자로 시험한다. 실제 외부 모델 검증과 구분한다.
- 실제 자료를 사용하는 첫 시험은 `research_incomplete_turn`으로 종료되어 성공 보고서를 저장하지 않았다. 후속 외부 모델 검증은 자동 승인 검토가 집계자료의 외부 전송에 대한 명시적 승인을 요구하여 중단했다. **실제 모델의 검색·인용·저장까지 이어지는 성공은 아직 확인하지 못했다.**

```sh
# 통합 저장소 루트. 설치된 테스트 환경을 선택한다.
PYTHONPATH=service/backend:agent/src:model:model/src \
  PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 ../agent/.venv/bin/python -m pytest -q \
  service/backend/tests/test_analysis_api.py \
  service/backend/tests/test_analysis_research_api.py \
  service/backend/tests/test_security.py \
  agent/tests/test_analysis_research.py

cd service/frontend
npm test
npm run build
```

원격 배포·커밋·푸시는 이번 작업에 포함하지 않았다.
