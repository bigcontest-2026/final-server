# Step 09 — 대응안 선택·수정·통합 보고서

현황 분석 보고서에서 사용자가 필요할 때 대응안 검토로 이어지고, 선택한 대응안만 모아 두 번째 보고서를 만드는 흐름을 구현한다. ③ 복지 매핑은 사용자가 별도 확인하는 범위로 유지한다.

## 화면 흐름

1. **현황 분석 보고서 → 대응안 검토하기**: 보고서의 지역·관측월·집단과 해석 한계를 작업 화면에 유지한다.
2. **대응안 추가·편집**: 기존 사업 활용 / 사업 보완 / 신규 예방사업 중 유형을 고른다. 이름, 대상, 분석과 연결한 이유, 실행 내용, 사전 확인 사항, 검토 의견을 작성한다.
3. **복수 선택·저장**: 체크한 대응안의 개수를 표시한다. 미저장 내용은 화면에 유지하며, 명시적으로 저장한 뒤 보고서를 생성한다.
4. **최종 보고서**: 저장된 선택과 수정 버전만 통합한다. 이후 대응안을 수정해도 이전 보고서는 그대로 보존한다.
5. **독립 재조회**: 저장된 보고서에서 현황 분석 / 예방 대응을 구분해 열람하고 내려받는다.

이번 대응안은 담당자가 직접 작성하거나 복지 리스트에서 사업을 가져와 검토하는 초안이다. AI가 현장 수요·사업 적합성·효과를 검증한 자동 제안으로 표시하지 않는다. 참고 사업은 `user_selected_unverified`로 보존하며, 기존 추천·복지 매핑 로직을 추가하거나 변경하지 않는다.

## UI·UX

- 기존 HERMES의 색상·글꼴·헤르미 디자인을 유지한다.
- PC에서는 분석 근거 / 대응안 목록·편집 / 선택 요약을 함께 표시하고, 작은 화면에서는 세로로 배치한다.
- 작성 전, 미저장, 저장 중, 저장 완료, 저장 실패·수정 충돌을 구분한다.
- 초안 사이를 이동해도 입력을 유지한다. 저장하지 않은 채 닫을 때 계속 편집 / 저장 / 변경 취소를 화면 안에서 선택한다.
- 보고서 작성 시 필요한 대상·실행 내용이 비어 있으면 해당 입력란으로 안내한다.
- 중복 저장·생성을 막고, 다른 화면에서 변경된 내용은 409로 알린다. 입력을 자동으로 덮어쓰지 않는다.
- 보고서 미리보기에서는 선택한 내용과 출처를 읽기 쉽게 보여주고, 내부 식별자·전체 저장 원문은 상세 영역으로 제공한다.

## 화면 연결

- **대시보드**: 선택한 지역·월의 기존 보고서를 조회한다. 없으면 기존 지역 분석 버튼으로 안내하며, 보고서 조회만으로 외부 조사를 실행하지 않는다.
- **전체 복지 리스트**: 사업을 대응안에 담을 때 연결할 현황 분석을 먼저 선택하고 지역·월·집단을 확인한다. 사업은 미저장 초안으로 들어가 사용자가 검토·저장한다.
- **저장된 보고서**: 현황 분석과 예방 대응을 별도 목록으로 조회·페이지 처리한다. 지역·월·성별·연령 필터를 저장된 보고서 범위에 적용한다.

## API

| 요청 | 기능 |
| --- | --- |
| `GET /api/model/analysis-reports/{id}/response-workspace` | 해당 분석의 대응안·수정 이력·생성 보고서 조회 |
| `PUT /api/model/analysis-reports/{id}/response-workspace` | 기대 버전과 함께 대응안·선택·의견을 원자적으로 저장 |
| `POST /api/model/analysis-reports/{id}/response-reports` | 선택한 대응안의 정확한 버전으로 통합 보고서 생성 |
| `GET /api/model/response-reports` | 부모 분석·지역·월·집단별 보고서 목록 |
| `GET /api/model/response-reports/{id}` | 불변 보고서와 Markdown 재조회 |

수정·생성은 기존 `investigate`, 조회는 `read` 권한을 사용한다. 별도 `response_workspaces.sqlite3`에 작업 상태·수정 이력·최종 보고서를 저장하고 기존 기관 결합 규칙을 적용한다. 동일한 선택·내용의 보고서 요청은 기존 보고서를 재사용한다.

선택하지 않은 대응안, 이전 수정 버전, 다른 현황 분석의 대응안은 통합 보고서에 포함하지 않는다. 생성된 보고서는 요청 시점의 원본 분석과 선택한 대응안 전체를 보존한다. 문서 원문과 사용자 입력을 HTML/Markdown 지시로 실행하지 않는다.

## 기존 기능과의 관계

- 새 대응안과 최종 보고서는 서버에 보관한다. 기존 브라우저 대화·검토·정책 초안 전체를 자동 이관하는 작업은 포함하지 않는다.
- 기존 사업 하나의 복지 대화·검토 보고서와 새 통합 예방 대응 보고서는 각각 유지한다.
- 이번 경로는 외부 모델이나 기관에 연락하지 않고 저장된 분석과 작성 내용을 사용한다.
- Step 08의 실제 AI 원인 조사 검증은 집계자료 외부 전송 승인 대기 상태를 유지한다. 이번 화면 검증은 외부 모델을 차단한 로컬 서버에서 수행한다.

## 검증

서버에서는 수정 버전·중복 생성·부모 범위·복수 선택·선택 버전·기관 권한·재시작 후 조회를 확인한다. 화면에서는 입력 유지·미저장 안내·충돌·참고 사업 인용·선택한 내용만 생성하는지를 확인하고 PC와 모바일에서 검토한다.

2026-10-25 로컬 검증:

- 관련 서버·관측 규칙·조사 검사 163개와 19개 하위 검사가 통과했다. 이후 목록 조건 검증 변경을 포함한 보고서·권한 검사 85개도 통과했다.
- 최종 전체 프런트엔드 252개 검사와 TypeScript·Vite 빌드가 통과했다.
- 외부 모델과 원격 복지 DB를 차단한 별도 로컬 서버에서 대응안 2건 작성·복수 선택·서버 저장·통합 보고서 생성·새로고침 후 재조회를 확인했다.
- 지도에서 선택 지역·월의 보고서만 조회되는 것, 복지사업을 선택한 분석의 미저장 초안으로 가져오는 것을 실제 브라우저에서 확인했다.
- 390px 모바일에서 작업 화면과 구조화된 보고서를 확인했다. 페이지와 대화상자에 가로 넘침이 없었다.
- 기존 HTTP 출처 링크의 보존, 긴 사업 원문을 편집 길이로 줄일 때의 안내, 요청과 다른 보고서·선택 버전의 거절, 선택하지 않은 대응안만 바꾼 뒤 기존 보고서를 재사용하는 경우를 확인했다.
- 이 검증은 외부 AI의 원인 조사 성공이나 자동 정책 제안·현장 효과를 검증한 결과가 아니다.
- 검증 뒤 기존 로컬 API(8011)를 새 코드로 재시작했다. 기존 분석 보고서 1건 보존, 새 대응안 작업 조회, 예방 대응 보고서 목록을 GET으로 확인했다. 실제 업무 저장소에는 시험 대응안·보고서를 추가하지 않았고 외부 모델을 호출하지 않았다.
