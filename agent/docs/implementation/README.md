# 복지 추천 구현 단계

## Step 10: 생애주기·지역 맥락 해석과 확인 필요 연결 — 2026-10-25

[Step 10 구현·검증](step10/README.md): 기존 10집단과 5% 활동 범주를 유지하면서 문헌을 참고한 연령별 확인 질문을 현황 보고서와 지역 조사에 연결한다. 확인된 지원 필요와 사업의 대상·내용·전달·비용 검토를 대응안에 저장한다. 아래 Step 08·09에서 제외했던 후속 분야 연결은 이번 사용자 요청으로 추가했다. 실제 지역 조사 실행 여부와 코드·오프라인 검증은 구분한다.

## Step 09: 대응안 선택·수정·통합 보고서 — 2026-10-25

[Step 09 구현·검증](step09/README.md): 현황 분석에 연결된 대응안을 작성·복수 선택하고 수정 의견과 함께 서버에 저장한다. 선택한 버전만 모은 예방 대응 보고서를 생성·재조회하며 지도·전체 복지에서 기존 분석을 찾아 연결한다. 기존 HERMES 화면을 유지하며 미저장·충돌·필수 입력·모바일 사용 흐름을 구분한다. ③ 매핑과 실제 외부 모델 조사 검증은 이번 범위에 추가하지 않는다.

## Step 08: 현황·원인 분석 보고서 — 2026-10-25

[Step 08 구현·검증](step08/README.md): 저장된 관측 보고서에서 공개 지역 맥락을 조사하고, 출처가 연결된 사실·가능한 원인·추가 질문을 별도 보고서로 저장한다. 실패·근거 미확보·완료를 구분하고 브라우저 기록 없이 서버 보고서를 조회한다. **③ 복지 매핑은 사용자 별도 확인으로 제외**했다. 실제 외부 모델의 전체 성공 검증은 집계자료 전송 승인 대기이며 오프라인 검사와 구분한다.

## Step 07: 활동 분류와 현황 보고서 저장 — 2026-10-25

서버의 `signal_rules.py`가 모델에서 받은 통신·카드 변화율을 동일한 규칙으로 분류한다. `welfare_pipeline.py`의 검색 경로와 현황 보고서가 이 공통 결과를 사용한다. LLM이나 화면에서 범주를 다시 계산하지 않는다.

### 분류 규칙

규칙 버전은 `activity-review-5pct-v1`이다. 원천별 `change_percent <= -5`를 충족하면 **5% 이상 감소**다. 모델의 기존 `rule.candidate`와 `rule.two_month_streak`는 0% 초과 감소 기준이므로 새 규칙의 발동 근거로 사용하지 않는다.

| 범주 | 코드 | 조건 |
| --- | --- | --- |
| 기준 이상 감소 미포착 | `no_threshold_decline` | 두 원천 모두 계산 가능하며 5% 감소 기준 미충족 |
| 단일 감소 관찰 | `single_source_decline` | 한 원천이 기준 충족. 다른 원천이 미확인이면 동시 감소는 미확인으로 보존 |
| 동시 감소 관찰 | `joint_decline` | 두 원천 모두 기준 충족, 우선 검토 보조 조건 미충족·미확인 |
| 우선 검토 후보 | `priority_review` | 두 원천 모두 기준 충족하고, 같은 5% 기준의 2개월 연속 감소 또는 현재 모델의 `robust.candidate=true` |
| 판정 보류 | `assessment_hold` | 기준 충족 원천이 확인되지 않은 상태에서 자료 누락·비교 불가가 있거나 관측 범위가 유효하지 않음 |

- 연속성은 **정확히 직전 달·같은 시군구·성별·연령** 자료의 변화율로 다시 계산한다. 과거 자료가 없거나 범위가 다르면 `null`이다. 현재 분류와 연속성 미확인을 별도로 보존한다.
- 모델의 상대적 이례성 후보는 기존 `Q>0` 및 강건 통계 `z>=3.5`의 연구용 근거다. 양원천 5% 감소가 없는 상태에서 이례성만으로 우선 검토 후보가 되지 않는다.
- 결측·비수치·NaN·무한대·bool을 0으로 채우지 않는다. 모델 전체 비교가 `unavailable`이어도 원천별 계산이 유효하면 그 원천의 관찰을 보존한다. 명시적인 `not_comparable`은 보류한다.
- I5·MOIS는 지역 배경, C3는 같은 카드 원천의 다른 과거 기준선이다. 위험점수로 합산하거나 범주 승격의 독립적인 표로 세지 않는다. 현재 I5 6집단을 활동 10집단으로 복제하지 않는다.
- `quality_status=hold`, 원 보류 사유, `operational_alert_allowed=false`를 유지한다. 5%는 초기 검토 규칙이며 고립 위험을 검증한 임계값이 아니다. **미포착은 안전 판정이 아니고, 우선 검토 후보는 고립 확정이 아니다.**

포함된 100개 관측의 회귀 결과는 **70 / 19 / 10 / 1 / 0**(위 표 순서)이다. 유일한 우선 검토 후보인 2025년 10월 춘천시 남성 20대에는 SKT 9→10월 경계 변경 보류 사유도 함께 남는다. 강남구 2025년 8월 남성 20대(-4.51%, -0.34%)는 현재 **기준 이상 감소 미포착**으로, 자동 복지 검색을 실행하지 않는다. 아래 Step 03~06의 동일 예시 추천 2건은 이전 규칙의 실행 이력이다.

### 첫 번째 현황 보고서 API

대시보드·기본 근거 분석·관측 목록도 `GET /api/model/behavior`의 `records[].activity_assessment`를 사용한다. GET은 같은 `classify_activity` 함수로 계산하며 보고서를 저장하거나 원인 조사 모델을 호출하지 않는다. 응답의 `classification_rule`과 `manifest_sha256`로 규칙·자료 버전을 확인한다. 직전 달 자료는 조회 필터·페이지 밖에 있더라도 전체 검증 번들에서 정확히 찾는다.

기본 근거 분석과 관측 목록은 `service/shared/hermi-activity-view.js`로 5개 범주별 건수·필터와 집단별 근거를 표시한다. 대시보드는 기존 상단 4카드와 지역 목록·지도·상세 배치를 유지하고 점수 자리를 활동 범주로 바꾼다. 지역·시도 표시는 수록 집단 중 먼저 검토할 범주와 해당/수록 집단 수를 함께 표시하며, 지역 전체 등급으로 해석하지 않는다. 미제공 지역은 활동 자료 없음으로 표시한다. 기본 근거 분석의 행정동 선택은 상위 시군구 참고임을 명시한다. `hermes_activity_views.py` 패치로 HTML 재생성 후에도 이 연결을 유지한다.

| 메서드·경로 | 기능 |
| --- | --- |
| `POST /api/model/analysis-reports` | 검증된 관측으로 보고서를 생성하고 저장 |
| `GET /api/model/analysis-reports?limit=20&offset=0` | 저장된 보고서 목록 조회 |
| `GET /api/model/analysis-reports/{report_id}` | 저장된 보고서의 구조화 결과와 Markdown 재조회 |

생성 본문은 `region_code`, `month`가 필수이고 `sex_code`, `age_code`를 선택할 수 있다. 성별·연령을 생략하면 해당 지역·월의 10집단을 표시하며, 없는 관측은 판정 보류로 남긴다.

```json
{"region_code":"11680","month":"202508","sex_code":"MAN","age_code":"20G"}
```

`analysis_reports.py`는 분류 이유·원천별 변화·연속성/이례성·I5/MOIS·정확히 연결된 C3·품질 한계를 보고서로 만든다. `analysis_api.py`는 번들의 해시·완료 상태·관측 키·연결 범위를 검증하고 두 자료 버전이 조회 도중 바뀌면 저장하지 않는다. 모델 자료가 없는 것과 번들 손상·누락으로 읽을 수 없는 것을 구분한다.

`analysis_report_store.py`는 `INVESTIGATION_DB_PATH`와 같은 디렉터리의 별도 `analysis_reports.sqlite3`에 불변 보고서를 저장한다. 스키마·범위·분류 규칙·자료 버전이 같으면 기존 `report_id`를 재사용하며 `reused=true`를 반환한다. 서버 재시작 후에도 조회할 수 있다. 기관 모드에서는 기존 기관 인증·권한과 DB 기관 결합을 적용한다. 원격 배포·기관 운영 검증을 완료했다는 의미는 아니다.

이 기본 산출물은 **현황·변화 신호 분석**이다. 외부 원인 조사는 `not_performed`, 대응 보고서는 `not_requested`로 남긴다. Step 08의 별도 조사 경로가 이 원본에 연결된 현황·원인 보고서를 생성한다. 기존 사업 추천의 원격 9개 분류↔I5 연결 기준 미확정 보류도 유지한다.

### 로컬 검증

통합 저장소 루트에서 `.venv/bin/python scripts/smoke_test.py --local-only`를 실행하면 포함된 번들·100개 관측의 분류·보고서 임시 저장·중복 재사용·재조회만 점검한다. 외부 복지 DB 조회는 실행하지 않는다. Windows에서는 `.venv/Scripts/python`을 사용한다. 선택적으로 `agent/tests/test_signal_rules.py`, `agent/tests/test_welfare_pipeline_standalone.py`에서 경계값·결측·전월 범위·원격 추천 보류 경로를 검증할 수 있다. 전체 API·화면 회귀의 현재 결과는 별도 실행 기록을 따른다.

## 현재 범위

조합 규칙 → 선택 태그 OR 검색 → 공식 사업 내용·지역·대상·기간 검사 → 명백한 불일치 제외 → 추천 이유·미확인 조건 표시. 지역 U의 실제 원인 조사와 욕구 확인은 후속 확장이다.

I5 고저 기준은 미정이며 위험 임계값을 부여하지 않는다. **활동변화는 Step 07의 5% 규칙**을 적용한다. Step 01의 외부 true/false/null 입력과 합성 태그 시험은 당시 구현 기록이며, 현재 관측 분류·공식 복지 분류 연결의 검증 범위와 구분한다.
