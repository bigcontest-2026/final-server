# Step 05 — HERMES 화면설계서 적용과 추천 그래프 연결

2026-10-25. `view_design/KakaoTalk_20261019_085608364*.png` 6장, `color_plate.jpg`, 헤르미 PNG를 기준으로 기존 final 화면을 HERMES 화면으로 교체했다. 지표·판단 엔진은 Step 03/04의 공통 그래프를 유지한다.

## 화면별 구현

| 화면설계서 | 구현 |
|---|---|
| 기본 PNG | 헤르미 중심 질문 홈, 질문 예시 4개, 공통 메뉴, 우측 접이식 에이전트 |
| `_01` | 전국 시도 탐색, 시군구·행정동 목록, I5 정렬 및 5영역, 상세 지도 지원 지역, 복지 이동 |
| `_02` | 해석 요약 → 카드 변화 추이 → 집단별 변화 → 이전 월 비교 → 성·연령 인구구성 |
| `_03` | 비교 셀·Rule·Robust 집계, 후보 목록과 상세 근거, 품질 보류, 선택 집단 복지 이동 |
| `_04` | 사업 목록, 관측 → 연결 근거 → 자격 미확인 3단 설명, 추천·제외·보류, 근거 저장 |
| `_05` | 검토 타임라인, 담당자·메모·후속 조치 상태, JSON 내보내기, 브라우저 PDF 인쇄 |

공통 상태는 지역·분석월·성별·연령이다. 전체 성·연령에서는 집단별 값을 나란히 제시하며 임의 평균하지 않는다. 복지 추천은 명시적으로 선택한 성·연령 집단으로 실행한다. 읍면동 I5에서 추천으로 이동하더라도 활동자료와 추천의 공간 단위는 상위 **시군구**다.

## 데이터 흐름

`지역/월/집단 → /api/model/welfare → welfare_graph → welfare_pipeline → 실제 I5·활동 번들 + ERD 임시 DB → 추천/제외/보류 → 화면`

- 지역 목록: `/api/model/regions`
- I5: `/api/model/survey-area`, 모든 페이지를 읽고 동일 코드로 결합
- 활동: `/api/model/behavior`, 해당 시군구의 2025.07–12 집단별 근거
- 추천: `/api/model/welfare`, Step 04의 서버 그래프 사용. 프런트에서 사업 매핑을 재계산하지 않는다.
- 입력 변경 시 기존 요청을 취소하고 이전 입력의 응답을 가린다.
- 추천 이유에 실제 통신·카드 변화율, 관련 I5 영역, DB 검색 근거와 미확인 조건을 표시한다.
- I5가 높은 이유, 개인 지원 필요, 정책 효과를 생성하지 않는다. context 모드이며 임계값은 미확정이다.

## 에이전트의 현재 범위

추천은 서버의 실제 LangGraph로 실행된다. 우측 대화는 현재 조회 결과를 활용하는 **정해진 질문 의도와 응답 템플릿**이다. 자유형 LLM 대화·외부 맥락 검색·기존 승인형 조사 그래프 전체 실행은 이 화면에 추가하지 않았다. 다른 지역을 질문하면 먼저 지역을 바꾸며 자료 로딩 후 질문을 다시 선택하도록 안내한다. 화면에도 자유형 LLM이 아님을 표시한다.

## 실행

API는 Step 04 README 설정으로 실행한다. 현재 로컬 API `http://127.0.0.1:8011`, 프런트 `http://127.0.0.1:5175/`.
프런트 실행 시 `MODEL_API_PROXY=http://127.0.0.1:8011`; Vite final 모드가 기본 HERMES 화면을 표시한다.
일반 환경에서는 `npm test`, `npm run build`로 검사한다. bundled Node 환경은 `node node_modules/vitest/vitest.mjs run`, `node node_modules/typescript/bin/tsc -b`, `node node_modules/vite/bin/vite.js build`를 사용한다.

## 남은 제약

- 복지 DB는 **가상 5사업**. 공식 분류+별도 I5 연결 ERD 구조이며 실제 사업 수집·운영 DB 교체는 후속이다.
- 전국 경계는 2018 탐색용이다. 최신 통계 경계가 아니며 전국 지수를 지도 색상으로 합산하지 않는다. 상세 경계 없는 지역은 실제 I5 목록으로 탐색한다.
- 검토 이력은 이 브라우저 localStorage에만 저장된다. 사용자 인증·서버 공동 이력·불변 감사 로그가 아니다. 후속 조치 상태는 현재 상태를 수정한다.
- JSON 생성 및 인쇄 버튼을 구현했으나 OS 저장 대화상자까지의 파일 저장은 자동 검증하지 않았다.
- 화면설계서의 예시 문구·원인·성과 수치는 실제 자료로 뒷받침되는 부분만 표현했다. 승인된 운영 경보나 개인 진단은 제공하지 않는다.
