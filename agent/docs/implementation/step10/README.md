# 생애주기·지역 맥락 해석

## 적용 흐름

`기존 5% 활동 범주 → 연령별 확인 질문 → 같은 지역·기간의 근거와 대안 설명 → 현황 보고서 → 확인한 필요로 분야 탐색 → 사업 조건 검토 → 요청한 대응 보고서`

분류 함수와 임계값은 바꾸지 않는다. 생애주기 가이드는 확인할 가설·질문을 선택하며 개인의 고립·외로움·지원 필요나 사업 자격을 판정하지 않는다. I5는 지역 인구구성 참고값, MOIS는 인구·세대 배경, C3는 동일 카드 원천의 과거 비교로 유지한다.

## 원문과 서비스 해석

- 김성아·강예은, 한국보건사회연구원, 『생애주기별 사회적 고립 및 외로움 실태와 정책 과제』, 연구보고서(수시) 2025-07, 2025년 12월. DOI: https://doi.org/10.23060/kihasa.b.2025.07
- 검토 본문: 19–24, 30, 39–40, 52, 57–62쪽. PDF 물리 쪽수는 본문 쪽수+8이다.
- 원문 SHA256: `54e127dd559bbe08562ea0c528f0cceb12e5b77361ca5b9936806f38037d2e5c`.
- 원문 첫 실증 연령은 19–29세, 현재 모델은 20–29세다. 60세 이상 집단에는 60–64세도 포함되므로 65세 이상 사업에 자동 대응하지 않는다.
- 연령별 고용·가족·관계·돌봄 질문은 서비스 해석 가설이다. 논문의 확정 원인표나 검증된 활동 감소 원인으로 제시하지 않는다. 문헌은 지역 확인 근거 수에 포함하지 않는다.
- 원문의 대상·급여·전달체계·재원 비교를 서비스 검토에 참고했다. 이용자 비용·접근성 확인은 서비스에 맞춰 추가한 항목이다.

## 보고서와 지역 조사

`analysis-report-1.1` 보고서는 `lifecycle-guide-kihasa-2025-07-v1`의 버전·내용 해시·문헌 출처와 원래 분석 범위의 모든 집단을 보존한다. 관측이 없는 집단은 질문만 제시하고 관측 없음으로 표시한다. 가이드 상태는 `questions_only`, 지원 필요는 `unconfirmed`이다.

`regional-context-research-1.1`은 각 집단의 가설 ID와 지역·월·성별·연령 범위를 입력으로 받는다. 결과의 `context_investigation.lifecycle_checks`는 관련 맥락·반대 맥락·미확인으로 구분한다. 확인된 지역 맥락에는 실제 조사 출처가 필요하며, 문헌만으로 지역 맥락을 확인한 것으로 처리하지 않는다. 가설에 유리한 근거 외에 달력·행사·기상·관측 범위 변경과 다른 집단의 변화를 함께 검토한다.

지역 집계 근거가 있어도 개인의 취업·은퇴·관계 상실을 확정하지 않는다. 과거 저장 보고서의 내용과 버전은 수정하지 않으며 새로운 가이드로 생성한 보고서는 별도 저장한다. 전체 PDF나 로컬 파일 경로는 조사 요청에 전달하지 않는다.

## 대응안과 분야 탐색

대응안의 `support_needs`는 9분야별 미확인/사용자 확인 상태·내용·근거를 저장한다. 확인 상태에는 내용과 근거가 모두 필요하다. 사용자 입력이라는 출처를 보존하며 모델 판정이나 개인 자격 확인으로 바꾸지 않는다.

`policy_review`는 대상·자격(`eligibility`), 지원 내용(`support_content`), 전달 방식(`delivery`), 재원·이용 부담(`finance_and_cost`)을 각각 미확인/확인/해당 없음으로 기록한다. 사업을 가져와도 네 항목은 미확인에서 시작한다. 수정 버전과 선택한 대응 보고서에 이 기록을 포함한다.

‘확인한 필요로 사업 찾기’는 저장된 확인 기록만 사용하며 사용자가 버튼을 눌렀을 때 조회한다. 단일 성·연령 집단이 지정되어야 한다. 전체 집단을 남성 20대로 대체하지 않는다. 조회 오류·0건은 사업 부재나 지원 공백으로 확정하지 않는다. 가져온 결과는 검토할 사업 후보이며 자격·모집·현재 제공 여부는 별도 확인한다.

명시적으로 확인한 필요를 검색할 때는 그 분야만 검색하며 미확인 활동 기반 분야를 섞지 않는다. 로컬 데모 저장소가 9분야 연결을 지원하지 않으면 `confirmed_needs_unsupported`로 보류한다. 화면은 사유와 함께 사업 탐색 보류를 표시하고 후보 가져오기를 막는다.

기본 관측 기반 탐색 분야에는 고정 순위를 두지 않는다. `welfare-context-topics-v1`은 확인 필요와 탐색 주제를 구분하고 같은 단계 안에서는 코드 순으로 표시한다. 기존 `welfare-service-actions-v3`의 원문 서비스 추출 정의와 등록된 해시는 유지한다.

## 검증 범위

실제 모델 100건의 범주는 기존 70/19/10/1건을 유지한다. 연령별 질문·누락 집단·가이드와 근거의 범위 검증, 이전 보고서 보존, 확인 기록 저장·재조회·버전, 검색 범위와 수동 조회 동작을 오프라인 검사한다. 실제 외부 모델 조사와 원격 사업 조회는 이 검사에 포함하지 않는다.

도식: `output/diagrams/welfare-mapping-20261025/welfare-index-category-map.{html,svg,png}`. 이전 도식은 같은 위치의 `.before-lifecycle.*`에 보존한다.

2026-10-25 검증: Python 전체 검사 694개 통과·30개 환경 조건 생략·79개 하위 사례 통과. 최종 추가 사업 검색 경로는 별도 42개·20개 하위 사례 검사 통과. 화면 전체 검사와 배포 빌드도 통과했다. API 8011·화면 5176을 재시작한 뒤 실제 모델의 춘천시 2025년 10월 남성 20대 보고서 `analysis_e916d52c57414269b3856eb81b245751`을 저장·재조회했다. 5% 범주와 자료 품질 보류, 생애주기 질문, 지원 필요 미확인, 원인 조사 미완료 표시를 실제 화면에서 확인했다. 대응안 검토 입력도 확인했으며 확인용 빈 초안은 저장하지 않았다.

화면 증거: `service/docs/screenshots/lifecycle-guide-live-20261025.png`, `service/docs/screenshots/lifecycle-policy-review-live-20261025.png`. 모델 조사·원격 사업 검색의 실제 성공 증거와는 구분한다.

## 보고서 간소화·대응안 도움 — 2026-10-25 후속 요청

저장된 보고서 창은 반복 소개·저장 완료 안내를 제거하고 지역·집단, 서버의 활동 범주·변화율·판정 이유를 먼저 표시한다. 생애주기 가이드는 기본 접힘으로 전환했다. 자세한 판정·자료 품질, 문헌·자료 기준과 보고서 전문은 펼쳐서 확인하며 저장된 원본과 내려받기는 보존한다.

대응안 안의 ‘헤르미에게 도움받기’는 `POST /api/model/analysis-reports/{id}/response-workspace/assist`를 명시 요청할 때만 호출한다. `draft`·`revise`·`review`를 실제 설정된 모델 제공자의 `decide(allow_tools=False)`에 연결한다. 저장된 분석을 서버에서 불러오고 사용자 초안과 구분하며 분석 ID·범위·유형·모드·근거 ID를 대조한다. 결과는 별도 미리보기이며 ‘대응안에 반영’ 후 기존 저장 절차를 따른다. 제안은 편집 문장만 변경할 수 있고 사용자 확인 필요·정책 검토·사업 참조 기록을 바꾸지 않는다. 요청 중 내용이 바뀌면 이전 제안의 반영을 막는다.

대응안 유형 세 버튼은 선택 후 접히며 `+ 대응안 추가`로 다시 펼친다. 로딩·실패·입력 유지·재요청을 구분한다. 외부 모델의 실제 응답 생성은 이 UI 확인에 포함하지 않는다. 설정된 구독 제공자의 준비 상태는 확인했다.

검사: 화면 전체 290개 통과 및 배포 빌드 성공, 도움 API·기존 대응안 API 관련 82개 통과. 실제 화면에서 보고서 간소화, 도움 입력·모드, 유형 버튼 접힘을 확인했다. 화면 증거는 `service/docs/screenshots/report-library-compact-20261025.png`, `service/docs/screenshots/response-agent-assist-live-20261025.png`이다.

글 작성 보조 호출은 사업 원문을 새로 조회하지 않는다. 근거 없는 금액·모집 일정·현행 운영 사실의 명시적 단정은 패턴 검사로 보류하고, 검토 제안·미정·원문 확인 질문을 구분한다. 이 검사는 완전한 사실 검증이 아니며 사업 원문 검토를 대체하지 않는다.

보고서 문구 후속 정리: 동일 집단 표시는 한 번만 노출하고, 우선 검토 후보의 두 판정 이유는 짧게 표시한다. 전체 판정 문장은 상세에 보존한다. 관리하는 보고서 JS·CSS에는 내용 해시를 버전 쿼리로 붙여 새로 연 탭이 최신 파일을 받도록 했다. 복지 리스트에서 새로 열어 범주·변화율·두 근거·접힌 상세·작업 버튼이 한 화면에 보이는 것을 확인했다. 화면 증거: `service/docs/screenshots/report-library-concise-welfare-live-20261025.png`. 화면 검사 290개와 빌드 통과.
