# HERMES 보고서 연결 UI 검토

검토일: 2026-10-26. 읽기 전용 코드 검토와 격리된 Node VM 확인을 수행했다. 서비스 소스 수정, 기존 테스트 재실행, 브라우저 조작, 외부 호출, 실제 DB 쓰기는 하지 않았다. 이 보고서만 생성했다. 프런트 전체 시험·빌드와 실제 화면 검증은 root 담당이다.

## 판정

- 명세 준수: **부분 충족**. 분석 계열 작업공간 키, 조건 불일치 차단, 복지 CTA의 저장 분석 선택, 명시적 보고서 생성, 선택적 다음 단계, 저장 비교 보고서 선택은 연결되어 있다. 다만 임시 저장 수명주기와 기존 편집기 입력 보존에 누락이 있다.
- 품질: **수정 필요**. 아래 세 항목을 해결한 뒤 완료로 판단하는 것이 적절하다. 다른 담당자가 검토하는 서버·저장 통합의 적합성을 이 판정으로 대신하지 않는다.

## 구체적 발견

### [P2] 기존 초안의 일반 새로고침·페이지 재진입에서 편집 내용을 잃는다

위치: `service/shared/hermes-complete.html:1537`, `:1542`, `:1550` 및 입력 보존 helper `:1458–1462`.

분석을 선택해 기존 초안 편집기의 주요 내용을 수정하고, 필터나 선택 분석을 바꾸지 않은 상태에서 **자료 새로고침**을 누르면 `renderPage()`가 `skeleton(page)`로 편집 DOM을 먼저 제거한다. 이 경로에는 `keepDraftEditor()`가 없다. 다른 메뉴로 이동한 뒤 초안 화면으로 돌아오는 일반 `navigate()` 경로도 보존을 호출하지 않는다. `studioHTML()`은 기존 서버 초안 또는 이미 보관된 값으로 재구성하므로 이번 편집분이 사라진다. `input` 이벤트에도 이 편집기 내용을 저장하는 처리가 없다.

격리 VM에서 실제 통합 HTML의 adapter를 실행해, `studioHTML()`로 편집기를 연 뒤 content 입력을 수정하고 다시 `studioHTML()`을 호출했다. 재구성 HTML에는 수정 문자열이 없었고 `S.livePolicyDrafts['case-a']`도 비어 있었다. 실제 새로고침 경로는 그 앞에서 DOM까지 지운다. 현재 `reportScope.test.ts`는 필터/분석 전환 시 보존을 검사하지만 같은 조건 재렌더나 메뉴 왕복은 다루지 않는다. DOM을 지우기 전 보존하거나 입력 시 분석별 상태를 갱신하고, 두 경로를 회귀 검사해야 한다.

### [P2] 충돌한 임시 초안에서 일부 입력은 열람·복사할 수 없다

위치: `service/shared/hermi-response-workspace.js:91–96`, `:374–378`.

브라우저 초안 생성 후 다른 화면에서 서버 저장본 버전이 올라가면 `restoreDraft()`는 복구를 막고, 안내는 필요한 내용을 미리보기에서 복사하라고 한다. 그러나 미리보기는 제목·대상·실행 내용·검토 의견만 표시한다. 분석 연결 이유(`rationale`), 실행 전 확인 사항(`checks`), 대응안 유형·선택 여부, 사업 참조, 네 가지 검토(`policy_review`)와 지원 필요 기록(`support_needs`)은 표시하지 않는다. 편집기는 복구 안내 중 비활성화되므로 그 값들에 접근할 다른 UI도 없다. **현재 저장본으로 계속**은 해당 임시 저장본을 삭제한다.

격리 VM에서 이유·확인 사항·사용자 확인 내용·근거를 각각 고유 문자열로 저장하고 서버 버전을 변경했다. `recovery.conflict === true`였고 `recoveryHTML()`은 네 문자열을 모두 누락했다. 충돌 정책은 유지하되 모든 보존 필드를 읽고 복사할 수 있게 표시하거나 전체 초안 내보내기를 제공해야 한다. `responseRecovery.test.ts`의 충돌 검사는 덮어쓰기 금지만 확인하며 전체 내용 접근성을 검사하지 않는다.

### [P2] 변경을 원래대로 되돌려도 중간 초안이 브라우저에 남는다

위치: `service/shared/hermi-response-workspace.js:56–65`.

저장된 제목 A를 B로 바꾸면 브라우저에 B가 임시 저장된다. 다시 A로 되돌리면 `dirty()`가 false가 되어 `persistDraft()`가 바로 반환하고, 저장돼 있던 B는 제거하지 않는다. 화면은 서버 저장 상태를 표시하고 닫기/이탈 보호도 작동하지 않지만 다음에 열면 이미 취소한 B를 복구할 초안으로 제시한다. 다른 필드를 편집 후 되돌려도 같은 문제다.

격리 VM에서 실제 controller를 실행한 결과는 `dirty: false`, `storedTitle: '고친 제목'`이었다. 로컬 상태가 서버 저장 스냅샷과 같아진 경우 해당 키의 임시 초안을 정리하고 상태 표시를 갱신해야 한다. 현재 복구 시험에는 변경 후 원복하는 수명주기 검사가 없다.

## 확인된 명세 연결과 검증 한계

- 기존 편집기 guard는 지역·월·성·연령·공간단위를 비교하고, 저장 직전 서버 사건을 다시 읽어 조건을 재검사한다. 입력 보존은 현재 필터/분석 전환에 연결되어 있다. 패치 재생성 검사는 실제 `hermes_draft_scope.py`를 실행하는 방식이다.
- 복지의 버튼과 보고서 요청 문구는 `attachProgramToReport()` → `chooseReport()` → 공통 작업공간으로 이어진다. 사업 설명 대화 자체는 유지된다. 선택 취소 시 작업공간을 열지 않는 검사도 있다.
- 분석 보고서는 저장 상태와 선택적 대응안 단계를 구분하고, 다른 지역 비교 선택기는 월·집단·공간 단위·다른 지역 여부를 확인한다. `investigate()`는 비교 ID별 요청 키와 응답 비교 ID를 검사한다.
- 공통 편집기의 브라우저 임시 키는 `workspace_analysis_report_id`를 사용하며, 복구는 사용자 선택으로 진행하고 충돌은 자동 덮어쓰기하지 않는다. 서버 저장·브라우저 저장 상태도 분리해 표시한다.
- native `dialog`, Escape 처리, 닫기 후 포커스 복귀, 입력 label, status/alert, 좁은 화면 CSS가 있다. 실제 키보드 순서·화면 확대·모바일 가림 여부는 브라우저 검증 결과를 기다려야 한다. 이번 검토에서 추가로 확정할 접근성/반응형 결함은 발견하지 않았다.
