# HERMES 분석·대응 보고서 연결 수정

## 요청과 범위
사용자는 첨부 서비스 흐름과 대조한 감사 결과의 문제를 우선순위대로 해결하고 UI·UX도 포함하라고 요청했다. 직전 감사에서 제시한 다섯 연결 문제와 화면 개선 방향을 구현 범위로 삼는다. 기존 Vite/HTML·FastAPI·SQLite 구조, HERMES 색상·캐릭터·한국어 표현을 유지한다.

## 접근과 선택
전체 화면을 새로 만드는 방법과 기존 기능을 연결하는 방법을 검토했다. 이번에는 기존 화면에서 분석 식별·보고서 경로·저장 상태를 고친다. 이 선택은 구현 판단이며 별도 디자인 개편 합의를 의미하지 않는다. 이미 수정 중인 작업본이 최신이므로 같은 파일을 보존하고 새 로컬 브랜치에서 작업한다. 기준 파일은 /private/tmp/hermes-report-flow-kftxc4s_/baseline 에 복사했다. 커밋·푸시·배포는 이번 작업에 포함하지 않는다.

## 동작
1. 원본 관측과 파생 원인 보고서는 한 분석 계열의 대응안 작업을 공유한다. 조사 전후 어느 보고서에서 열어도 저장한 대응안·버전·완성 보고서가 보인다. 완성 보고서의 원래 분석 스냅샷은 수정하지 않는다. 기존 양쪽 작업공간의 저장 내용도 잃지 않는다.
2. 대화의 기존 초안은 화면의 지역·월·성·연령과 선택 분석이 다르면 초안 구성·연결 저장을 막고 분석 선택을 안내한다. 가져오기 스크립트 재실행으로 수정이 사라지면 안 된다.
3. 복지사업 설명 대화는 유지하되 보고서 작성 CTA는 분석 선택 → 공통 대응안 편집 → 명시적 보고서 생성으로 연결한다. 사업 설명 답변을 지역 예방 대응 보고서로 오인시키지 않는다.
4. 사용자가 저장된 다른 지역 보고서를 선택하면 서버가 동일 월·집단·공간단위와 실제 저장 근거를 검증해 비교 조사에 전달한다. 비교 ID·범위·자료 버전은 조사 결과에 보존한다. 비교가 없는 기존 조사도 호환한다. 다른 비교 요청은 잘못 재사용하지 않는다.
5. 대응안 편집은 분석별 브라우저 임시 저장과 복구 안내, 서버 저장 상태, 페이지 이탈 보호를 갖춘다. 서버 저장과 임시 저장을 구분하고, 최신 서버 버전과 충돌하는 초안을 조용히 덮어쓰지 않는다.
6. 현황 보고서와 예방 대응 보고서의 이름·선택적 다음 단계·현재 분석 조건을 일관되게 표시한다. 기존 보고서 열람·내려받기·지도 연결·키보드 사용·좁은 화면을 보존한다.

## 제약
- 기존 미커밋 변경과 실제 runtime DB를 덮어쓰거나 삭제하지 않는다.
- 원본 보고서와 완성 예방 보고서는 불변이며, I5·활동 단위·품질 보류·운영 경보 불허 계약을 유지한다.
- 외부 LLM 호출·DB 쓰기·기관 연락 없이 합성 제공자와 임시 DB로 검증한다.
- 의존성을 추가하지 않고 현재 스택과 테스트 도구를 사용한다.
- UI에 내부 식별자·DB·구현 상세를 불필요하게 노출하지 않는다.

## 검증
원인 조사 전후 대응안 유지, 두 경로 기존 내용 보존, 조건 변경 차단, 복지 CTA의 분석 연결, 동일 조건 비교 입력/출처/중복·불일치 거부, 새로고침 복구·저장 충돌을 회귀 검사한다. 이후 프런트 전체 시험·빌드, 백엔드 전체 시험과 실제 로컬 화면을 확인한다.
